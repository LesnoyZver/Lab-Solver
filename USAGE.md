# USAGE — как пользоваться скиллом `lab-solver` и не сжигать токены

Документ для человека. Модель его не читает.

## Зачем это

Агент отправляет модели **всю историю чата на каждом шаге**. Поэтому цена шага
растёт по ходу работы: первый шаг дешёвый, тридцатый — в разы дороже.
Один лишний цикл «посмотрел → уточнил → проверил ещё раз» стоит дороже, чем
десять осмысленных действий в начале.

По логам 14 реальных прогонов (7–9 ноября) видно: из 937 вызовов инструментов
около четверти — служебные, то есть их можно было не делать.

## Быстрый чек-лист перед отправкой (30 секунд)

1. **Один чат — одна работа.** Не досылайте в тот же чат вторую лабу.
2. **В сообщении сразу:** файл задания + преподаватель + номер списка
   (номер списка и ФИО достаточно один раз — они сохранятся в `settings.json`).
3. **Один файл**, а не папка с материалами.
4. Если в задании нужна конкретная среда, нотация или инструмент — скажите это
   в том же сообщении (иначе агент будет их искать).

## Худшие практики

Действия, которые стоят много токенов модели, но делаются руками за секунды.

| Что просят у модели | Сколько это стоит | Что сделать руками |
|---|---|---|
| «Проверь ещё раз, всё ли правильно в отчёте» | 2–4 шага, полное перечитывание .docx | Открыть файл, `Ctrl+F` по `{{`, пролистать нумерацию заданий |
| «Сделай скриншоты с реальной Ubuntu / виртуальной машины» | 40–90 шагов: Docker, OrbStack, Parallels, SSH, запись экрана. В логах был прогон на 114 шагов | Выполнить команды самому, скопировать вывод в `.txt` и отдать файл |
| «Разберись, почему не читается PDF» | 5–10 шагов установки библиотеки в разные места | Один раз: `python3 -m pip install -r requirements.txt` |
| Пять правок подряд («поправь ещё вот это… ещё вот это») | Каждая правка — новый полный контекст | Собрать все замечания и отправить **одним** сообщением |
| Продолжить работу через час в старом чате | Контекст уже большой, каждый шаг дороже | Новый чат + файл задания заново |
| «Покажи, как устроен `build_report.py` / шаблон» | 5–15 тыс. токенов на чтение кода | Открыть в редакторе или `git diff` |
| «Сделай PDF-версию, чтобы проверить вёрстку» | Скилл это запрещает, агент потратит шаги на объяснение | Открыть `.docx` в Word/LibreOffice |
| Не ответить на вопрос агента (про преподавателя и т.п.) | Агент ждёт и повторяет вопрос | Ответить сразу, одним сообщением |
| Прислать сразу несколько работ | Всё уйдёт в один контекст, цена растёт | По одной работе на чат |
| «Перепиши отчёт целиком» | Полная перегенерация всех заданий | Сказать конкретно, что и где поменять |
| «Сверь отчёт с заданием, всё ли на месте» | Перечитывание задания и отчёта | Сравнить нумерацию заданий глазами |
| Просить «оптимизировать/улучшить» текст без критерия | Много итераций без результата | Дать точный критерий или пример |

### Отдельно про среду

Скилл сознательно **не** запускает виртуальные машины, контейнеры, SSH и
автоматизацию GUI. Если задание требует реальную ОС:

- нужен вывод команд — выполните их у себя и приложите `.txt`;
- нужны графические окна — либо скриншот из вашей среды, либо честный текст
  в отчёте. Агент скажет об этом сам, если среда недоступна.

## Что скилл делает дешево — не микроменеджерьте

- разбор задания (`.docx`, `.pdf`, `.txt`) одной командой;
- расчёт варианта и заполнение титульного листа;
- сборка и самопроверка `.docx` (заголовки, `{{…}}`, markdown, комментарии в коде);
- отчёт сразу рядом с заданием, с правильным именем `ЛР4.docx` / `ПР1.docx`;
- скриншоты из текстового вывода программы.

## Проверка готового отчёта за 30 секунд

1. Титульный лист: ФИО, группа, преподаватель, вариант.
2. Нумерация и формулировки заданий совпадают с заданием.
3. Нет `{{` и `[FILL IN]` (поиск по документу).
4. Код без комментариев, без markdown-звёздочек.
5. Нет выводов, которых не просили.

## Если что-то пошло не так

- Сборка напечатала `VIOLATIONS` — пришлите эти строки одним сообщением, этого достаточно.
- Жалуется на пустого преподавателя — укажите ФИО (и должность, если нужна).
- Файл не появился — проверьте папку рядом с заданием.

## Служебные команды

```bash
# проверить окружение: шрифт для скриншотов, Graphviz, pypdf, шаблоны
python3 ~/.dsh/skills/lab-solver/scripts/build_report.py --doctor

# разобрать задание одной командой (вместо ручных python3 -c)
python3 ~/.dsh/skills/lab-solver/scripts/build_report.py --read "задание.pdf"
python3 .../build_report.py --read "задание.docx" --max-chars 8000

# собрать отчёт сразу рядом с заданием (имя ЛР/ПР<номер>.docx)
python3 .../build_report.py data.json --next-to "/путь/к/заданию.docx"

# проверить готовый файл
python3 .../build_report.py --check "ЛР4.docx"
```

Личные данные: `~/.dsh/skills/lab-solver/settings.json` (номер списка, ФИО,
группа, язык отчёта, нотация диаграмм). В git не попадает.
